# S5 durable evidence publication decision

Decision date: 2026-09-12. Scope: ASDEV public-experience `S5-02`/`S5-03` acceptance evidence only. This document selects a publication path; it is not an evidence receipt, owner visual disposition, software release, or deployment authorization.

## Decision and rationale

Use a dedicated **GitHub prerelease in this repository** for a reviewed, sanitized evidence set for one exact candidate SHA. The tag format is `evidence-s5-<40-character-candidate-sha>` and must resolve to that candidate commit. Title and notes must say **“Evidence only — no application release or deployment”**, name the candidate SHA, source run/attempt, capture environment, scope and limitations, and must not claim owner acceptance. Do not use a `v*` version tag, the latest-release URL, a normal software-release title, or a mutable branch URL. The existing GitHub Releases facility avoids a new storage provider; public asset URLs are non-Actions HTTPS URLs that the current validator can retrieve and hash. A prerelease is still publicly visible in this public repository.

GitHub's current release documentation supports uploaded assets and prereleases; [release assets](https://docs.github.com/en/rest/releases/assets) expose a stable `browser_download_url` and digest. [Immutable releases](https://docs.github.com/en/code-security/concepts/supply-chain-security/immutable-releases) are a separate repository setting. The observed latest release `v1.1.0` reports `immutable: false`; **do not call this evidence immutable** or assume retention is guaranteed. Treat URLs as durable only while a fresh unauthenticated retrieval and SHA-256 check pass. A deletion, replacement, permission change, or failed retrieval reopens acceptance; never silently substitute a new asset under an accepted manifest. If repository policy later enables immutable releases, prepare all assets in draft and verify the setting before publishing; do not change settings as part of S5.

## Publication contract

1. Freeze the source candidate and run/attempt. Inspect the actual files and metadata before upload. Only synthetic or explicitly consented, sanitized public-route evidence is eligible. Exclude customer URLs, report tokens, contact data, cookies, credentials, authenticated traces, private logs and PII. Redaction must be reviewed, not inferred from filenames. Do not publish the old Actions ZIP wholesale.
2. Inventory each accepted screenshot, recording, trace and raw performance result separately. Preserve locale, viewport, theme, state, capture conditions, raw failures and limitations. The validator reads each artifact as a local file and remotely; therefore each manifest `relativePath` must resolve inside the verification root and each `durableUrl` must be that file's direct release-asset download URL, not the release page, Actions artifact URL, an expiring signed redirect or an aggregate ZIP. Each asset must fit the current 16 MiB remote validation limit and 10-second retrieval timeout; if it does not, keep the criterion `UNVERIFIED` until an admitted validator/storage solution exists. Do not hide or downsample required evidence merely to pass.
3. Compute SHA-256 from the reviewed bytes, publish a draft prerelease with the complete sanitized asset set, then publish and retrieve every referenced asset from its public URL. Compare remote bytes and recorded hash. Retain a manifest copy with exact candidate/base SHA, run/attempt, asset URLs/hashes, evidence conditions, review identity and explicit limitations. Draft/private/inaccessible releases do not satisfy the contract.
4. After publication, run the existing S5 manifest validator on the complete local tree, including remote retrieval and provider-backed independent-review verification. This is a **future gate, not an executable acceptance claim today**: the trusted validator requires an `APPROVED` GitHub PR review at the exact candidate/base and attesting the final evidence-scope SHA-256. PR #26 is already merged; its six retrieved reviews are `COMMENTED` and do not attest that scope. Do not relabel them accepted or create a duplicate PR solely to manufacture provenance. The validator also requires checkout `HEAD` to equal candidate `08d64742282cb7456ffbbc6077baa29d505a0741`. Dispatching the current workflow on `main` checks out a newer SHA, whereas the old candidate's workflow does not contain the trusted validator. Before claiming hosted acceptance, admit and verify a genuine review/validation execution path that preserves exact candidate identity and current fail-closed checks; until then trusted S5 validation is `BLOCKED`, even if all assets are retrievable. A GitHub release asset digest or self-authored manifest review field alone is not acceptance. Preserve failed, missing, partial and unavailable results honestly. Record the published tag, release/asset IDs, hashes, validation command/output and retrieval time in the PR/ledger without putting sensitive data into release notes.
5. Ask the owner to inspect the exact candidate visual matrix and record an explicit disposition with candidate SHA. Independent code review, green CI, the evidence prerelease and this decision cannot substitute for owner visual acceptance. Only then advance the governed S5-04…07 chain; staging/Production, release identity and deployed SHA remain separately gated.

## Status and rollback

As of this decision, no evidence prerelease or accepted manifest has been verified, owner visual disposition remains `UNVERIFIED`, and the trusted-review/hosted-validation path is `BLOCKED` as described above. The known Actions artifact `9890025924` for candidate `08d64742282cb7456ffbbc6077baa29d505a0741` has a recorded expiry of 2026-09-17; it is a source to inspect, not a durable publication. The existing software Release workflow fails in semantic-release on recent `main` runs; this decision neither fixes nor bypasses it. A documentation rollback is an ordinary PR revert. If an evidence asset is later found unsafe, restrict/remove it promptly, mark dependent acceptance invalid, and republish a separately versioned, fully revalidated set rather than rewriting evidence history.
